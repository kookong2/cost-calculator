# 대행 계산기 개발 프롬프트

## 역할

이 작업은 `cost-calculator` 대행 계산기의 기능 개발, 개선, 리팩터링 및 버그 해결을 위한 전용 작업이다. 저장소 루트의 `AGENTS.md`와 이 문서를 처음부터 끝까지 읽고 준수한다.

## 작업 시작 절차

1. `git status`, 최근 커밋, 저장소 파일 구성을 확인한다.
2. `index.html`, `sw.js`, `manifest.webmanifest`에서 요청과 관련된 부분만 읽는다.
3. 사용자의 요구사항을 한 문장으로 다시 정의한다.
4. 기존 계산식과 화면 동작 중 보존해야 하는 내용을 구분한다.
5. 요구사항이 충분하면 바로 구현하고, 결과가 크게 달라지는 모호함만 질문한다.

## 구현 원칙

- 요청과 관계없는 디자인, 계산식, 문구, 파일 구조를 변경하지 않는다.
- 현재 순수 HTML/CSS/JavaScript 구조를 우선한다.
- 같은 숫자나 정책값이 여러 곳에 반복되면 요청 범위 안에서만 명확한 상수화를 검토한다.
- 금액 계산은 부동소수점, 반올림 시점, 원 단위 표시를 명시적으로 다룬다.
- 입력 오류는 조용히 잘못 계산하지 말고 사용자가 이해할 수 있게 안내한다.
- 모바일 화면, 복사 버튼, 모드 전환, 설치형 PWA 동작을 함께 고려한다.
- 서비스워커 캐시가 수정 결과를 가리지 않도록 캐시 버전과 갱신 흐름을 확인한다.

## 검증 기준

- 변경된 계산 공식은 최소한 정상값, 0, 빈 값, 소수 입력으로 확인한다.
- 기존 원가 계산과 역산 모드가 모두 정상 동작하는지 확인한다.
- 결과에는 불필요한 접두사 없이 요구된 숫자와 단위만 표시되는지 확인한다.
- 브라우저 콘솔 오류가 없는지 확인한다.
- 모바일 폭에서 입력, 버튼, 결과가 잘리거나 겹치지 않는지 확인한다.
- 서비스워커 사용 시 새 버전과 새로고침 후 결과가 일치하는지 확인한다.
- 별도 자동 테스트 환경이 없으면 수행한 수동 검증 항목과 한계를 명확히 기록한다.

## Git 및 배포

- 기존 사용자 변경사항을 덮어쓰거나 되돌리지 않는다.
- 요청받지 않은 파일을 커밋에 포함하지 않는다.
- 원격 푸시와 GitHub Pages 배포는 사용자 승인 전에는 수행하지 않는다.
- 배포 전 변경 파일, 계산 검증 결과, 캐시 갱신 여부를 보고한다.

## 완료 보고 형식

- 변경 내용
- 검증 결과
- 남은 문제 또는 확인이 필요한 사항
- 배포 여부와 다음 단계

구체적인 개발 요청이 없으면 임의로 코드를 수정하지 말고 준비 완료만 알린 뒤 사용자의 요구사항을 기다린다.
